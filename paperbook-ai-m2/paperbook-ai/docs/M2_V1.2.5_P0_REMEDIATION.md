## 1. P0-1：截断/过滤后仍生成"成功产物"

### 1.1 根因（三处，逐条）

| # | 位置 | 原行为 | 为什么算 P0 |
|---|---|---|---|
| 1 | `src/vision/backends/qwen_vl.py:195` `_loads_json` | 解析失败时从尾部切到最后一个 `}`/`]` 并补齐括号重试 | 半截 JSON（可能已丢掉 `safety` 段）被"救"成合法对象，后续按 `pass` 默认值出成功 C2 |
| 2 | `src/vision/contracts.py:140`、`:230` | 超过 `MAX_ITEMS=99` 直接 `break` | 100 块文字只发 99 块，**没有超限信号**，下游看到的是合法成功产物 |
| 3 | `src/vision/worker.py` VLM 段 | 先写 C2、再建 sidecar，且不清旧文件 | C2 写成功、sidecar 失败时留下半套；安全拦截时上一轮旧 C2 仍在目录里，可能被下游当成本次结果 |

### 1.2 改法

- `qwen_vl.py`：`_loads_json` **删除全部切片逻辑**，只接受两种输入——整段是 JSON 对象，或整段被 ``` 围栏包住。其余抛 `VlmIncompleteOutput`（→ Worker `2001/transient`，pipeline 契约错误）。
- `contracts.py`：新增 `ContractLimitError(kind, actual, limit)`；两处 `break` 改为 `raise`。
  Worker 映射为 `1004` + `detail={"kind","actual","limit"}`；pipeline 映射为 `ERROR_INPUT_TOO_LARGE=1004`。
  **不写任何产物**（C1/C2/sidecar 都不落盘）。
- `worker.py:217` 新增 `_discard(paths)`；VLM 段把 `_outputs_for` 提到安全门禁之前，3004 时清理 `c2`/`sidecar`；
  `C2 写入 → 读回 → sidecar 写好` 包进 `try/except BaseException`，任一步失败即删两者再抛（部分写入回滚）。
- 追加校验：`status=ok` 但既无 objects 又无 description → `ContractViolation`（9001），不接受"空成功"。

## 2. P0-2：旧索引安全旁路

### 2.1 根因

`src/vision/index.py:build_from_vlm` 只看 `status`，**从不解析 `vlm_doc["safety"]`**。于是：

- 手工改过的 `vlm.json`（`status=ok`、`safety` 缺失或 `pass=false`）能直接建索引；
- `scripts/build_index.py` 用宽松 `json.load` 读入，重复 `safety` 键会被后者覆盖。

旧路径 = 只要有人用 CLI/脚本重建索引，就能绕过 Worker 门禁拿到"可点读对象"。

### 2.2 改法

- `index.py:25` 新增 `UnsafeIndexError`；`:147` 在 `build_from_vlm` 里加
  `record = parse_safety(vlm_doc.get("safety"))`，`not record.ok` → `UnsafeIndexError(record.message())`。
- `index.load`（`:300`）改用 `strict_loads_object`，重复键/NaN → `ValueError("索引文件结构不可信")`。
- `scripts/build_index.py:49` 改用 `loads_object`；`:61` `except UnsafeIndexError` → 打印 `[BLOCK]`、计入 `blocked`、不写索引；`:88` 有拦截则 `return 2`。

### 2.3 回归测试

`test_index_rejects_safety_missing`、`test_index_rejects_nonempty_flags`、`test_index_rejects_string_pass`、
`test_index_load_rejects_duplicate_keys`、`test_build_index_script_blocks_unsafe_page`（断言脚本 rc=2 且不生成索引文件）。

1. **真实绘本版面与跨页关联准确率**：没有获得授权的真实绘本语料，也没有标注规范。只能给方法与合成样例，**不宣称准确率**。

3. **真实服务端取消证据**：Ollama 的 `/api/chat` 无单任务取消接口；HTTP 断开不等于服务端停止计算。需要 M1 提供容器级终止（cgroup kill / Job Object）与终止回执，M2 侧只能证明"客户端退出 + 派生进程被杀"。
4. **Sidecar 冻结**：候选协议（`contract_status="candidate"`），需 M1/M2 联合签认后才能称冻结。
5. **供应商真实调用**：需授权、预算与项目负责人批准。

以上五项不会写成"已通过"。
