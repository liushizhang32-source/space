## 1. 这一版做了什么

把 M2 的 OCR/VLM 从“人工 CLI + 整页负责制”改成**可被 M1 拉起的一次性 Worker**：

- 一个进程只跑一个 stage（`ocr` 或 `vlm`），跑完写 `result.json` 后退出；
- 接受 M1 的 `job/page/generation/revision/epoch/attempt/token` 七元组并逐项回显；
- 安全判定 fail-closed：结果是 3004 时**不写 C2、不写 sidecar**；
- VLM 成功后生成 `vision_refs/0.1` sidecar，`c2.sha256` 绑定落盘原始字节；
- 去掉内部整页超时与自主重试——30 秒墙、杀进程树、重试退避全部交回 M1。

**没有**改冻结 C1/C2、没有改公共 Schema、没有建 Jobs、没有动 M1 代码。

## 5. 关键行为约定

1. **安全**：只有 `safety.pass is True` 且 `flags` 为空才发布 C2；否则 3004，
   M1 应把 Page 置 blocked、不调下游。
2. **OCR 无字**：返回 `code=0` + 合法 `status=empty` 的 C1（不发 3001）。
3. **错误码**：1004/1006 输入问题；2001 模型调用；2002 超时；3004 安全；9001 契约。
   `transient` 只作建议，M2 自己不重试。
4. **路径**：所有产物路径必须是 attempt 目录内的相对路径；`..`、绝对路径、越界一律拒绝。
5. **环境**：M1 需放行 `VISION_*`、`QWEN_VL_*`、`PADDLE_*`；**不要**放行
   `VISION_EMIT_EXTRA`。

## 6. 已知限制

1. 交接协议没有“上一阶段 C1 路径”字段，VLM 缺 `inputs.c1` 时会在进程内再跑一次 OCR
   （真实模型 +8–11 s），建议 M1 补字段或约定必填。
2. sidecar schema 是候选协议，字段名与路径待三方确认；M2 不把它当公共契约。
3. 相对路径环境变量由 Worker 锚到模块根，但仍建议 M1 传绝对值。
4. 被 M1 硬墙杀掉时没有 `result.json`，M1 需按超时 2002 处理。
5. 真实 VLM 仍可能给出泛化标签（“人物/袋子”），这是模型能力问题，不在本版范围。

## 7. 复现命令

```powershell
# 全量

# 单次 OCR（stub）

$env:VISION_VLM_BACKEND="http"; $env:QWEN_VL_BASE_URL="http://127.0.0.1:11434/v1"
$env:QWEN_VL_MODEL="qwen2.5vl:3b"; $env:QWEN_VL_TIMEOUT="25"
python scripts\m2_vision_worker.py <attempt>\request.json
```
