## 1. 本轮关闭的问题

### 1.1 重复 JSON 键覆盖安全字段（P0）

**复现（整改前）**

```python
json.loads('{"safety":{"pass":true,"flags":["violence"],"flags":[]}}')
# -> {'safety': {'pass': True, 'flags': []}}
```

解析后 `flags` 已变成 `[]`，后续任何 schema 校验都看不到 `violence`，最终产出 `pass=true, flags=[], code=0`。

**整改**

| 位置 | 改动 |
|---|---|
| `src/vision/strictjson.py`（新） | `object_pairs_hook` 逐对象查重（递归覆盖嵌套与数组内对象）；`NaN`/`Infinity` 由 `parse_constant` 拒绝；`StrictJsonError(kind, key)` |
| `src/vision/backends/qwen_vl.py` | 模型输出改用 `strictjson.loads`；重复键抛 `VlmUnsafeOutput(kind, key)` |
| `src/vision/worker.py` | `VlmUnsafeOutput` → `code=3004`、`detail={kind,key,stage}`、不写 C2/Sidecar；`request.json`/C1/`out.json` 改严格解析，结构问题 → `9001` |
| `src/vision/pipeline.py` | 旧入口（CLI）同样把 `VlmUnsafeOutput` 映射为 3004，杜绝旁路 |
| `src/vision/vlm_child.py` | 子进程 `job.json` 改严格解析 |

**证据**：`tests/test_strictjson.py` 11 项，含 `flags`/`pass`/`safety` 对象重复、数组内重复、`NaN`、Worker 3004 且无产物、pipeline 3004 且无 C2、请求重复键 9001。

### 1.2 取消确认被错误响应骗过（P1）

**整改**：`src/vision/backend_task.py` 新增 `_confirmation_from_body()`，只有同时满足下列条件才置 `terminal_confirmed=true`：

1. HTTP 2xx；
2. 响应体是合法 JSON 对象；
3. `cancelled` 为原生布尔 `true`；
4. 回显的 `task_id`/`backend_task_id` 与本次一致；
5. 回显的 `generation_id`/`attempt_id` 与本次一致；
6. 无 `terminal=false`、`state∈{running,queued,pending}` 等矛盾字段。

未确认时保持 `may_retry=false`、`may_publish=false`，并记录 `cancel_status`/`cancel_body`/`detail`。

**证据**：`tests/test_backend_task.py` 新增 5 项（错 task_id、错 generation、非 JSON、矛盾响应、全标识回显）。

### 1.3 安全门禁统一（上轮遗留，本轮补完旧入口）

`pipeline.run_page` 在 `build_vlm_document` 之前调用 `evaluate_vlm_safety`，不通过即 `StageError(3004)` 且不落盘 C2；与 Worker 共用同一函数。`tests/test_pipeline.py` 有 `test_pipeline_blocks_untrusted_safety_with_3004`、`test_pipeline_blocks_nonempty_flags_with_3004`。
