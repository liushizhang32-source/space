# M2 V1.2.1 整改报告

> 对象：独立审查对 M2 V1.2 的退回意见（P0 4 条 + P1 6 条）。
> 范围：`paperbook-ai/src/vision/**`、`tests/**`、`scripts/**`、`docs/**`；
> **未改**冻结的 C1/C2（`docs/API_v1.0.md`）、未改公共 API、未接入 dev。

## 0. 一句话结论

10 条整改全部落地，新增 20 项专项回归；`tests/run_all.py` **117 passed, 0 failed**。
安全结论不再能被字符串/数字冒充、VLM 不再自己补 OCR、产物不会互相覆盖、
超量输入不再静默截断。

## 1. P0-1 安全字段严格校验

**问题**：`"true"`、`1` 会被当成通过；flags 异常/缺失没有统一 fail-closed。

**改法**

- 新增 `src/vision/safety.py::strict_safety(payload)`，只解析**原始 JSON**：
  - 非对象 → `safety_missing`
  - 缺 `pass` → `safety_pass_missing`
  - `pass is not True` → `safety_pass_not_true`（`"true"`、`1`、`"false"` 全拒）
  - `flags` 非数组 → `safety_flags_not_list`；元素非字符串 → `safety_flag_not_string`；
    空白 → `safety_flag_blank`；超 200 字 → `safety_flag_too_long`
- `qwen_vl.parse_safety` 直接委托 `strict_safety`，删除旧的宽松 `parse_bool` 路径。
- 后端结果再加一层 `evaluate_vlm_safety`：`safety_source` 必须是 `"model"`
  （stub/补出来的结论 → `safety_source_untrusted`），`pass=true` 但带 flag →
  `safety_conflict`。只有同时通过两层才写 C2。
- 安全阻断统一 `3004`；`3001` 仍只表示 OCR 未识别到文字。

**测试**：`test_safety_string_true_is_blocked`、`test_safety_number_one_is_blocked`、
`test_safety_missing_source_is_blocked`、`test_safety_blank_flag_is_blocked`、
`test_safety_flags_not_list_is_blocked`、`test_safety_pass_with_flag_is_conflict`；
另有 `test_schema_compat.test_parse_safety_is_fail_closed`、
`test_vlm_parse_treats_false_string_as_false`（期望两条原因）。

## 2. P0-2 VLM 执行边界

**问题**：常驻 HTTP 服务下，杀 Worker 客户端不能证明模型计算已终止。

**改法**

- 新增 `M2_VLM_EXEC=subprocess`：VLM 在子进程 `vision.vlm_child` 里跑，
  Worker 超时/异常时 `taskkill /F /T`（整棵树）+ `kill()` + `communicate()` 回收。
- 新增 `docs/VLM_EXECUTION_BOUNDARY.md`：明确三层可验证性，**如实声明**
  M2 不能单方面证明服务端计算停止，给出服务端取消接口/每 attempt 容器两条路。
- 本机实测杀树+回收 1.038–1.045 s（3 次）。

**测试**：`test_child_process_timeout_is_killed_and_reaped`（sleep 30，timeout=1s，
断言 15 s 内完成）。

## 3. P0-3 产物路径碰撞

**问题**：`result.json`、C1、C2、sidecar 可能互相覆盖。

**改法**

- `writer.write_json_exclusive`：`O_CREAT|O_EXCL` 直接建目标文件，
  已存在/符号链接/并发抢先 → `FileExistsError`；异常时删半截文件。
- `worker._outputs_for`：先规范化路径，再查
  「产物之间」「产物 vs `result_path`」同路径，最后单独查存在性；
  三者都落在 attempt 私有目录内。
- `result.json` 用 `write_json_atomic`（允许同目录重复执行），`os.replace`
  不会写穿符号链接。

**测试**：`test_path_collision_between_artifacts_is_rejected`、
`test_artifact_colliding_with_result_path_is_rejected`、
`test_existing_output_is_not_overwritten`、`test_symlinked_output_is_rejected`。

## 4. P0-4 Sidecar 契约

**改法**

- `refs.py` 输出 `contract_status: "candidate"`，明确“候选、未签认”。
- `identity` 同时提供嵌套块与**扁平镜像**（顶层 7 项），兼容只读顶层的校验器。
- `appearance.clothing` 恒 `null`，类型声明 `str | null`；`confidence` 两种形态都带
  `calibrated: false`；新增 `c1_sha256`，把 sidecar 同时绑到 C2 与 C1。
- 未定义 `canonical_id`/`character_id`。

**测试**：`test_sidecar_candidate_contract_fields`（`contract_status`、7 项 identity、
扁平镜像、clothing、calibrated、`c1_sha256` 与文件字节一致）。

## 5. P1-5 VLM 必须接收 M1 的 C1

- 删除“缺 C1 就进程内再跑一次 OCR”的兜底；缺 `inputs.c1` 直接 `9001`。
- 新增三重关联：`inputs.c1_sha256`（原始字节）、`page_id`/`book_id`/`page_no`、
  `status ∈ {ok,empty}`、`image_width/height` 与当前图片一致；
  `inputs.image_sha256` 与实读图片字节一致。
- **tokens**：`inputs.c1_sha256` 缺失或格式非法 → `9001`。

**测试**：`test_missing_c1_is_contract_error_not_internal_ocr`、
`test_c1_sha256_mismatch_is_rejected`、`test_c1_cross_page_is_rejected`、
`test_c1_old_revision_size_is_rejected`、`test_image_sha256_mismatch_is_rejected`。

## 6. P1-6 路径安全（symlink/junction/TOCTOU）

- `_is_linklike`：`S_ISLNK` 或 Windows `FILE_ATTRIBUTE_REPARSE_POINT`。
- `_reject_link_components` 逐段检查父目录，`_resolve_under` 拒绝绝对/`..`/越界。
- 图片先 `read_bytes()` 再交给 `preprocess.load_page_image(..., data=...)`，
  解码与 EXIF 都从同一份内存字节读，避免“校验后被替换”。
- 校验发生在跑模型前，坏请求退出码稳定为 2。

**测试**：`test_symlinked_output_is_rejected`、`test_absolute_image_path_is_rejected`、
`test_path_traversal_is_rejected`。

## 7. P1-7 输入校验不扩大

- `input_guard.ALLOWED_FORMATS` 从 `{JPEG,PNG,WEBP,BMP,TIFF}` **收窄**为
  `{JPEG,PNG,WEBP}`；体积/像素上限保持 V1.1 的原值（25 MiB / 40 MP）。
- 未擅自新增 D02 参数；`M2_MAX_OCR_BLOCKS`/`M2_MAX_OCR_CHARS` 只是**内部安全阀**，
  默认值与冻结契约的 `MAX_ITEMS=99` 对齐，且超限即拒绝，参见 P1-8。

**测试**：`test_unsupported_image_bytes_rejected_before_backend`（含 PDF/GIF magic）。

## 8. P1-8 禁止静默截断

- 去掉 `MAX_ITEMS=99` 的静默 `break` 路径在 Worker 侧的影响：Worker 先统计
  `len(lines)`/总字数，超 `MAX_OCR_BLOCKS`/`MAX_OCR_CHARS` → `1004`，
  `detail={"kind":"ocr_blocks","actual","limit"}`，**不写 C1**。
- VLM objects 超过 `MAX_OBJECTS=12` → 解析层抛 `VlmOutputOverflow` → `1004`，
  `detail={"kind":"objects","actual","limit"}`，**不写 C2**。
- `contracts` 里的 99 条上限仍是冻结契约的一部分，Worker 只是“在写盘前就拒绝”。

**测试**：`test_ocr_blocks_over_limit_is_structured_1004`、
`test_objects_overflow_is_structured_1004`。

## 9. P1-9 置信度

- 删除 `0.75` 假值。`_parse_confidence` 只接受有限实数 `0<v≤1`；
  bool/字符串/NaN/Inf/越界 → 缺失。
- 缺失记 `0.0` 并累加 `confidence_missing`，写入 envelope `detail` 与 sidecar 的
  `{"value":null,"kind":"unavailable","calibrated":false}`。
- sidecar 的 `_confidence` 同样拒绝 bool/NaN。

**测试**：`test_confidence_rejects_bool_nan_and_string`（3 个物体 → 全 0.0、
`confidence_missing==3`、无 NaN 落盘）。

## 10. P1-10 异常处理

- 后端初始化失败 → `ContractViolation` → `2004`（transient）。
- 输入类型错误/坏 JSON/路径非法 → `9001`/`1004`/`1006`，都带 `result.json`。
- 写产物失败（已存在/链接）→ `9001`；`result.json` 写失败 → 退出码 1 + stderr。
- 请求文件本身读不了/不是对象 → 仍尽量写 `cwd/result.json` 再退出。

**测试**：`test_missing_identity_is_bad_request`、`test_backend_none_is_contract_error`、
`test_existing_output_is_not_overwritten`。
