## 2. 根因

**P0-01**：`worker._understand_via_child` 用标准库 `json.loads` 读取子进程产物。标准库对重复键采用
“后者覆盖前者”，而 VLM 返回的 `safety` 恰在末尾，任何重复字段都会覆盖真实风险。
根因不是“忘了校验”，而是**子进程边界上换了一种解析器**——主进程严格、子进程宽松，形成旁路。

**P0-01b**：子进程失败只有 `{"ok": false, "reason": ...}` 一种形状，主进程无法区分
“安全输出不可信”和“模型网络失败”，只能统一按 2001 处理，等于把安全拦截降级成可重试错误。

**P0-02**：`_loads_json` 在 `invalid_json` 时从尾部回退到最后一个 `}`/`]` 并补括号重试。
这条路径的本意是“救回被截断的 JSON”，但它无法判断截断发生在 `safety` 之前还是之后，
因此**可能把已丢失安全段的半截输出变成合法产物**。

## 4. 整改方案

1. **统一解析器**：所有 JSON 入口（请求、C1、子进程 `out.json`、HTTP 外壳、`job.json`）
   一律走 `strictjson.loads_object`；重复键、`NaN`/`Infinity` 直接拒绝。
2. **区分失败语义**：
   - 安全字段不可信（重复键、非有限数字、flags 缺失/非空/空白、pass 非布尔 true、来源不可信）→ **3004**，不写 C2/Sidecar；
   - 输出不完整（无 JSON、半截、非对象）→ **2001 + transient**，不写产物，允许 M1 按白名单重试；
   - 普通模型/网络失败 → 2001/2002，沿用既有映射。
3. **删除截断修复**：不补齐括号、不从尾部裁剪；宁可判“不完整”，不制造成功。
4. **门禁收敛**：`SafetyBlocked`/`VlmUnsafeOutput` 在 worker、pipeline、frame 三个入口都映射为 3004。
5. **子进程契约**：`vlm_child` 的失败结构增加 `error_kind`，但仍是私有 IPC 字段，不进入公共 C1/C2。

## 6. 新增测试设计

- **重复键**：顶层/嵌套/数组内重复 `pass`、`flags`、`safety`；请求 JSON 重复 `page_id`。
- **截断**：半截 `safety`、缺右括号、无 JSON 对象；断言不再被补齐、且不写产物。
- **语义保持**：子进程 `error_kind=VlmUnsafeOutput` → 3004；普通失败不冒充安全。
- **产物零落盘**：3004/2001 时 C2、Sidecar、`result.json` 的 `artifacts` 均为空。
- 现有 `tests/test_v124_p0.py`（10 项）已覆盖上述；`run_all` 计入 160 项基线。

现状：`backend_task.cancel()` 只有在响应含 `cancelled: true` 且 `task_id/generation_id/attempt_id`
逐项一致时才置 `terminal_confirmed=True`；未确认时不发布、不重试。

要关闭 P1-01，还需要**真实服务端证据**，计划：
1. 起 Ollama，提交一个长任务，记录 `backend_task_id` 与 `/api/ps` 的模型驻留状态；
2. 调用取消接口（若 Ollama 无单任务取消，则记录“无此能力”，改为容器级 kill）；
3. 采集三份证据：取消响应、`/api/ps` 前后对比、GPU/CPU 占用回落曲线；
4. 明确结论只能是“服务端确认终止”或“服务端不具备能力，需 M1 容器兜底”，不得用 Mock 替代。
